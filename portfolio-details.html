An internal HR system built on Laravel and MySQL

A Human Resource Management System used internally to handle employee records, daily attendance, leave requests, and company policies in one place, replacing the spreadsheets the HR team had been maintaining by hand. I work on it as a PHP Laravel Developer, covering the database schema, the backend business logic, the REST API layer, and the interfaces built on top.

Project Overview

The brief, the approach, and what came out of it

The Brief

HR was tracking employees, attendance, and leave across scattered spreadsheets. They needed one system where records were accurate, searchable, and visible only to the right people.

The Approach

I modelled the database first, then built each module as a Laravel controller with Form Request validation and an API endpoint, so the same logic serves both the web screens and future integrations.

The Outcome

A system the HR team uses daily. Records live in one place, leave approvals leave an audit trail, and adding a new module now takes days rather than weeks.

What I Handled

How the system came together, phase by phase

Phase 01

Requirements & Scope

Sat with the HR team to understand their existing process, then defined which modules were essential for the first release and which could wait.

Phase 02

Data Model

Designed the MySQL schema with migrations and Eloquent relationships covering employees, departments, attendance entries, leave types, and balances.

Phase 03

Application Build

Built the controllers, REST endpoints, and Blade interfaces module by module, with authentication, role based access, and middleware in place from the first draft.

Phase 04

Optimisation & Handover

Profiled slow listing queries and fixed them with eager loading and indexes, tested the endpoints in Postman, and documented them for the rest of the team.
